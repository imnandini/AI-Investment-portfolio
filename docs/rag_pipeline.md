# Document research pipeline

Uploaded PDF bytes are read in memory, hashed with SHA-256 and deduplicated per owner. No source URL is fetched. MIME and PDF headers must match; size is limited to 5 MB, 100 pages and one million extracted characters. Encrypted, malformed and scanned/empty PDFs have explicit persisted statuses. OCR is not implemented. A failed record can be deleted and uploaded again.

PyMuPDF extracts page text. Chunking stays within pages, prefers paragraph/line boundaries and overlaps 200 characters by default (1,600-character chunks). Short tables stay together when they fit; layout/table semantics are not reconstructed. Metadata retains company, document kind, reporting period, publication date, source URL, page, hash and ingestion time. Source URLs are validated HTTP(S) links and never download instructions.

`EMBEDDING_PROVIDER=hash` uses normalized 384-dimensional lexical feature vectors. This is an offline baseline, **not semantic understanding**. `none` supports keyword-only retrieval. To enable semantic retrieval, install `backend/requirements-models.txt`, provision a trusted 384-dimensional SentenceTransformer model locally, set `EMBEDDING_PROVIDER=sentence_transformers` and `EMBEDDING_MODEL_PATH`. Remote code and model downloads are disabled. Reindex each document after changing models using `POST /documents/{id}/reindex`. Model identity filters prevent mixing incompatible indexes. A local cross-encoder can be selected with `RERANKER_MODEL_PATH`; it is optional and has not been benchmarked in the default configuration.

PostgreSQL stores vectors in pgvector, with an HNSW cosine index and an English full-text GIN index. Queries filter by owner before matching company, kind, period, publication range and page. Keyword and vector candidates are limited to 40 each; reciprocal-rank fusion merges them (k=60), optional reranking considers at most 20, and responses contain at most 10 passages. SQLite has a bounded reference implementation for tests and small corpora (5,000 candidate chunks). Hash-only matches require lexical overlap to avoid treating feature collisions as evidence.

Answers are extractive quotations with document/page citations. There is no configured generative LLM, remote embedding call or web search. Retrieved text cannot choose tools, access secrets or change system behavior. Empty results explicitly state insufficient evidence. A relevant excerpt does not establish the truth of a claim. Cross-period comparisons are not inferred. Review reports flag simple potentially inconsistent same-company/same-period numeric claims and retain the passages for inspection; this does not replace full accounting reconciliation.

Index writes use a transaction savepoint. An embedding failure cannot leave partial chunks. A reindex failure rolls back to the previous index. Initial indexing failures require a fresh upload because original PDF bytes are not retained. Delete removes chunks; all of that owner's saved chat/reviews are also erased to remove any retained excerpts. Backups require separate retention management.
